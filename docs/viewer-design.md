# 查看器前端（壳子）设计说明

> 这份文档只讲**壳子**：一块画布、两条边栏、一条指纹条怎么摆，为什么这么摆。
> 数值口径不在这里，一律以 `data/denominator.json` 与 `docs/caliber.md` 为准。

> **状态**：本文件记录 2026-11-24 那次替换。旧壳子（顶栏 112 px 那一版）已删除，
> `viewer/` 下现在只有一套：模板、注入后的单文件、以及它的瘦身数据。

产物：

| 文件 | 说明 |
|:--|:--|
| `viewer/viewer-template.html` | 模板（占位符是 `/*__DATA__*/`，重导时用） |
| `viewer/acd-viewer.html` | 注入数据后的单文件查看器，双击即开（`acd-viewer.lnk` 指向它） |
| `viewer/acd-views.json` | 三个切片的瘦身数据（每条边第 7 位带 `src` 逐层出处） |
| `docs/preview.jpg` | 首屏截图（README 首图，中文界面） |
| `docs/preview.en.jpg` | 同一首屏的英文界面（顶栏 `中/EN` 切换后） |
| `docs/preview-detail.jpg` | 点选焦点节点后的证据页（右栏逐边四格） |

## 1 旧壳子的七个问题

不是审美问题，是**读数的路被挡住了**。

| # | 症状 | 后果 |
|:--:|:--|:--|
| 1 | 顶栏 112 px 里塞了标题、锚点、3 个视图、搜索、适应/回到焦点、3 个边模式、**14 个图例条目**、一行统计 | 没有层级，眼睛不知道从哪开始 |
| 2 | 导出器随数据下发了每个视图的 `note`（如「运行时边如何补上静态看不到的调用」），**界面从不显示** | 三个视图各自的论点在界面上消失，只剩三张图 |
| 3 | 默认状态把 681 条边全部以 0.32 alpha 铺开 | 变成蛛网；焦点节点反而被淹没，最该看的东西最不显眼 |
| 4 | 节点填充色 = 5 类归因，边颜色 = 4 层来源，共 9 个色相，11 px 上分不开 | 双重编码互相打架：蓝既是「静态」也是「有入边」 |
| 5 | 底部指纹（md5 / commit / configure）11 px、`#5c6b7a`，绝对定位压在画布上 | 全仓最可信的那件东西，是全屏最看不见的那行字 |
| 6 | 搜索只搜当前切片，不说明范围 | 搜一个真实存在的 FFmpeg 函数得到「无匹配」，看起来像图算错了 |
| 7 | 没有 permalink、没有「复制证据」、没有导出 | 想引用一条边，只能截屏；预热期最需要的就是可引用 |

## 2 四条设计原则

1. **一屏三栏，各管一件事**：左栏「读」（视图与口径），中间「看」（图），右栏「核」（这条边的证据）。顶栏只放全局，底栏只放指纹。
2. **颜色只归边，归因归文字**：层用色相（静态蓝 / 运行时绿 / 汇编紫 / 注册表琥珀 / 交叉近白），`gap_class` 不再抢色相——`HAS_INBOUND` 中性灰，只有异常归因才染色并染到**文字**上（视图③ 的 58 个疑似死码，名字本身就是红的）。
3. **默认稀疏，按需展开**：屏幕上同时出现的函数名有预算（随缩放 14 → 28 → 44 → 70 → 110 → 全部）；没预算的退化成环上的点；hover / 点选才把那一个节点的边点亮。
4. **指纹常驻、不压画布**：md5、commit、configure 进底栏，永远可见、可复制；导出 PNG 时烧进图里。

## 3 七处结构性改动

### 3.1 三栏 + 指纹条（替掉 112 px 顶栏）

```
┌ 顶栏 56：标识 · 全局搜索（带范围） · 复制链接 · 导出 PNG ┐
├ 296 视图与口径 ┬ 画布 ┬ 336 证据页 ┤
└ 底栏 34：图锚 md5 · commit · configure · 生成时间 ┘
```

底栏右侧还写了一句实话：`载入 3 切片 · 414 节点 · 1,147 边（非全图：全图 114,175 边）`。

### 3.2 视图卡：把每个视图的论点搬到台面上

每张卡五行：标题 → `note`（论点）→ 焦点函数名 · 文件 → **层构成条**（5 段色条，边长按边数）→ `单源 / 交叉 / 节点` 三个数。
视图①：`681 边 · 单源 606 · 交叉 75`；视图②：`250 / 185 / 65`；视图③：`216 / 211 / 5`。

点一张卡切换视图，等于换一段论证。

### 3.3 环上的径向标签（这是壳子最费工的一处）

数据是**同心环布局**（焦点在圆心，`dist=d` 落在第 d 圈），不是从左到右的分层图——所以标签不能按「行」排。

做法分三步：

1. **按角度分扇区选点**：把环切成 `budget` 个扇区，每扇区取度数最高的一个函数。名称于是沿环**均匀成冠**，而不是挤在一段弧里（v1 直接按度数取前 N 个，结果全堆在顶部）。
2. **分离轴（SAT）防重叠**：每个标签是有向矩形，按度数从高到低放，压住的一律退回成点。
3. **按可用长度截断，且保留尾缀**：标签朝外延伸，先算它沿书写方向到画布边的距离，再决定截多长；截断从中间挖，**保留 `_8` / `_10` / `avx2` 这类区分位**——视图② 全是 `ff_hevc_sao_horiz_filter_8_10_avx2` 这种名字，砍掉尾巴等于把标签废掉。

左半环的标签整体翻转 180°，保证不倒着读。

### 3.4 焦点卡在圆心、深度环有刻度、底纹随图走

- 圆心不再是一个小白点，而是一张**白卡**：`FOCUS · L0 · 出 159 / 入 0` + 函数名 + 文件；有异常归因时右上角挂一枚色标（视图③ 挂「疑似死码」）。圆心那片空地正好放它。
- 每圈画一条 5% 白描边，圈内挂 `L1 · 159` 这类刻度，视图③ 的 `L1 · 5 / L2 · 29 / L3 · 58` 一眼能数。
- 26 px 点阵底纹随平移移动，拖拽时有参照物。

### 3.5 边：让辐条成扇，内部边只留成淡网

681 条边全画就是蛛网。分两档：

| 边的位置 | 默认 alpha | 说明 |
|:--|--:|:--|
| 焦点 → 第一圈（辐条） | 0.19 | 成扇，视图①里就是「一个分发函数指向 159 个解码器」 |
| 同圈 / 圈间的内部边 | 0.07 | 只作为质感存在，`≥2 源` 的再多 0.04 |
| hover / 点选节点的边 | 0.92 | 一次性只点亮一个节点的那一束，宽 1.5–1.9 px |

这样默认画面是**可读的**，而「合流才有的边」靠「单源 / 交叉」按钮和 hover 逐个取证，不靠一眼糊上去。

### 3.6 证据页：把「哪几层各自看到」画成四格

这是这次改造真正的重点。每条边右侧四个 8 px 小格 = `静态 / 运行时 / 汇编 / 注册表`，亮起即该层**独立**看到这条边；`≥2 源` 就是两个格子同时亮。

同一页还有：调用点 `libavcodec/fitsdec.c:293`、`trace 106,568`、归因定义（只在非 `HAS_INBOUND` 时展开）、出/入边列表（按源数排序，超过 40 条明说「仅显示前 40，共 N」）。
底部两个按钮：**复制证据**（一段纯文本，含文件行号、源、trace、图锚）与**复制链接**（`#v=decode&n=<node>`）。

> 为什么这条要在数据里加字段，见 §4：四格不能靠前端猜。

### 3.7 指纹条、permalink、PNG

- 底栏三件套可一键复制；`configure` 太长铺不下，截断 + 悬停展开。
- 选择节点后地址栏 `#v=…&n=…` 随时可变（`replaceState`，不产生历史垃圾），贴到 issue 里对方打开就停在同一条边。
- 「导出 PNG」走 2× 像素，把标题、论点、图锚 md5、commit、边数**烧进图里**——转发出去自带出处。

### 3.8 中英双语 + 切片标注（2026-11-24 增补）

**双语走单文件运行时切换**，不做两份 HTML：翻译量相同（约 100 条），单文件省 290 KB，且链接能带 `#lang=` 让中文读者分享出去别人也看得懂。

- 词条集中在模板顶部 `const I18N={zh:{…},en:{…}}`，两侧键集严格相等（`smoke_test.py` 有机器断言）；取词只经 `TR(key)`，静态文案用 `data-t / data-tt / data-tp` 三类属性在 `applyI18n()` 里刷。
- 语言按三级解析：`#lang=` > `localStorage('acd-lang')` > `navigator.language`（非 `zh` 开头一律 `en`）。顶栏 `中 / EN` 一键切，`setLang()` 重跑全部渲染函数 + `draw()`，并 `replaceState` 把 `lang` 写回地址栏。
- 导出的 PNG 水印也走 `TR()`，英文界面导出的图里标题与水印都是英文。

**切片标注补了「占比」，并把话说清楚**：内置的是 **3 个手挑切片**（focus + depth 2/2/3 的邻域），合计 414 / 1,147，占全图 38,697 / 114,175 的 **1.07% / 1.00%**。四处同标：

| 位置 | 文案（中文界面） |
|:--|:--|
| 顶栏徽标 `#slicebadge` | `SLICE 1/3 · 160 / 38,697 节点（0.41%）` |
| 画布下 `#slicehint` | `本视图 681 / 114,175 边（0.60%）· 非全图；全量查询用 scripts/query.py` |
| 右栏账目 / 空态 | `切片 160 / 38,697 节点（0.41%）· 681 / 114,175 边（0.60%）—— 非全图` |
| 页脚右下 `#mf-right` | `载入 3 切片 · 414 节点 · 1,147 边（非全图：全图 …，占 1.07% / 1.00%）` |

导出的 PNG 也带切片行与占比，转发出去不会只剩一张漂亮图。

## 4 数据契约的变化（向后兼容）

旧版的一条边是 6 元组 `[caller, callee, layer, 源数, 调用点, trace]`。现在加第 7 位：

```json
["fits_decode_frame@…", "av_bswap32", "multi", 2,
 "libavcodec/fitsdec.c:293", 106568, ["runtime", "static"]]
```

模板对两种形态都能吃：没有第 7 位时，四格矩阵自动退化成 `n 源` 徽标（绝不猜“是哪两层”）。

`scripts/export_views.py` 改了三处（**默认行为不变**）：

1. `links.append(...)` 末尾加 `sorted({s for s in (pay.get("sources") or []) if s})`；
2. 新增 `--template / --out-html / --out-json` 三个可选参数，缺省仍是 `viewer/viewer-template.html`、`viewer/acd-viewer.html`、`viewer/acd-views.json`；
3. docstring 补了新参数的用法。

日常重导只要一条命令（默认路径就指向这一套）：

```bash
python scripts/export_views.py --graph acd_graph.json
```

想另存一份、不覆盖默认产物时，才需要显式指定：

```bash
python scripts/export_views.py --graph acd_graph.json \
    --out-html viewer/_scratch.html --out-json viewer/_scratch.json
```

实测三个切片与旧版逐项一致（160/681、160/250、94/216），只有数据体积从 0.22 MB 涨到 0.23 MB，涨的全是 `src` 数组。

## 5 口径对齐（照 `caliber.md` §11 抄的）

| 位置 | 写法 | 为什么 |
|:--|:--|:--|
| 归因图例 | `疑似死码`，定义里写明「疑似，未证实」 | 不说「死代码」 |
| 归因图例脚注 | 「六分类里的 UNCOVERED 当前图为 0，故只列 5 类——不是少了一类」 | §4 的原话 |
| 右栏空态 | 「本视图 382 条边只有运行时插桩看得到——纯静态解析拿不到」 | 只说这一层能看到什么，不做跨口径相减 |
| 搜索无命中 | 「本切片 160 个节点内无匹配。查看器只载入 3 个切片，全图 38,697 个调用方节点未载入——不是查不到，是没装进来」 | 主动交代边界 |
| 底栏 | 载入 3 切片 / 414 节点 / 1,147 边（非全图） | 同上 |
| 全文 | 不出现「覆盖率」 | 只用「触达率」，且本壳子不重复报这个数 |

## 6 已知未做（如实列出）

1. **边不能单独点选**——现在只能通过节点进它的边列表；边级选中的命中测试要另做一层，值不当。
2. **没有缩略图 / 面包屑**——三个切片最大 300 节点、半径固定，暂时用不上；上到全图必须补。
3. **键盘可达性不全**：`Esc / F / /` 有，图例与视图卡仍是 div/button 混用，未做 role / tabindex。
4. **窄屏未专门适配**：1366×768 可用（左栏需滚动），再窄会开始挤。
5. **英文界面已做运行时切换，口径与问答也已译**（`caliber.en.md` / `faq.en.md`），但 `reproduce.md` / `anchors.md` / 本文仍只有中文；英文读者的完整路径是 `README.en.md` → `GUIDE.en.md` → `caliber.en.md` → 报告英文版。
6. **`confidence` 字段没进证据页**：图里每条边有 `confidence`，这一版只用了 `sources`；要不要把「置信度」也摆出来，取决于它在你口径里的地位——现在不摆，是怕它和「源数」抢同一个位置。
