# 口径与边界（Caliber & Limits）

> 中文版即本文 ｜ **English → [caliber.en.md](caliber.en.md)**
>
> The definitions, the known limits, and the rules behind every number in this repository.
> Numbers live in exactly one place: [`data/denominator.json`](../data/denominator.json). This file holds **no value tables** — by design.

本文回答一个读者真正会问的问题：**这些数字凭什么可信，以及它们在哪里不准。**

它只写**定义、边界、纪律**，不写数值表。数值的唯一来源是 [`data/denominator.json`](../data/denominator.json)（与图 `b357bf8e…` 同批，随 Release 同包分发）。**同一个数字在仓库里出现两处，就是缺陷。**

---

## 1 五条纪律

### 1.1 单一真源
一个指标 = 一个定义 + 一个分母 + 一个数据源。指标定义散落多处即违规。

### 1.2 禁跨口径相减 / 相除
分子分母口径不同 → 不得相除；不得相减。若确需复用同一分母，必须显式声明「这是同一分母的复用」，而不是默认成立。

本仓最容易踩的两处：
- 「主源边数」与「独占贡献」口径不同，**不可相加**（见 README 来源分账表下的注）；
- `target_set` 与 `touched` 不是同一集合，**不可直接相除**。

### 1.3 证据等级
`运行时代码（runtime） > 静态语法 > 注册表推断 > LLM 推断`

任一分歧标 `unobserved`，**不删、不合并、不猜**。对外给出的边数与触达率必须附带来源分布，而非只给一个总数。

### 1.4 口径名强制标注
引用数字必须写全口径名。**裸写「覆盖率」「无入边」「死代码」= 违规**，因为本仓每一个词都至少有两个口径（见 §2.5–§2.6）。

### 1.5 绑定锚与 stale
任何派生数字都绑定一个图锚（md5）。**图 md5 变 → 所有派生数字 stale，禁继续引用，须重算。** 见 §8。

## 2 术语与定义

### 2.1 `pk`（target_set 匹配键）
```
pk(n, f) = n + '@ffmpeg-src#' + norm(f).replace('/', '#')
norm(f)  = 剥掉 'ffmpeg-src/' 前缀
```
`norm` 不可省：目标清单里的文件路径有两种写法（带 / 不带 `ffmpeg-src/` 前缀），不归一化会构造出双前缀键 `name@ffmpeg-src#ffmpeg-src#…`，导致**全部目标被误判为缺口**。

匹配必须使用 `[name, file]` 二元组，**不能用纯名字列表**——后者 file 为空，缺口会虚高一个数量级。

### 2.2 key 三形态

| 形态 | 示例 | 性质 |
|:--|:--|:--|
| 带 workspace 前缀 | `name@ffmpeg-src#dir#file` | 规范形态 |
| 无 workspace 前缀 | `name@dir#file` | 早期缺陷，已修（当前为 0）|
| 裸名 | `name` | 设计：多副本聚合 / 外部符号 |

### 2.3 `target_set` 三档

| 档 | 判定 |
|:--|:--|
| **A** 已是调用方节点 | `pk(n,f)` 在 `edges` 键集中 |
| **B** 只作为被调用方出现 | 不在键集，但出现在任一 `calls` 的被调用方中 |
| **C 真缺口** | 既不是调用方、也不是被调用方 |

### 2.4 `callee_id` 三形态

| 形态 | 判定 | 性质 |
|:--|:--|:--|
| 精确键 | 含 `@` 与 `#` | 可 BFS |
| 裸名 | 不含 `#` | 设计（不写 ID）|
| 空 | `null` | 外部符号 / 设计留空（见 §3）|

### 2.5 无 `callee_id` 双口径

| 口径 | 定义 | 用途 |
|:--|:--|:--|
| **严格** | `callee_id ∈ edges.keys()` | **一切校验用严格口径** |
| 宽松 | 允许归一化到精确键 | 只用于归因，不用于判定 |

宽松口径会掩盖问题，因此任何「一致率」必须声明用的是哪一个。

### 2.6 无入边四口径（**四个数各有定义，禁混用**）

| 口径 | 定义 | 性质 |
|:--|:--|:--|
| ① 原始字符串 | 该 key 不作为任何边的被调用方出现 | 图论直算 |
| ② 裸名归一化 | 裸名被引用，**或**同裸名的任一精确键被引用，即算有入边 | 图论直算（须展开到精确键）|
| ③ identity 去重 | 同名同文件只算一次 | 图论直算 |
| ④ 分母工具口径 | 分母工具输出的 `without_inbound_identity` | 工具口径，含汇编/裸名回退 |

> ① 与 ② 的差不是缺陷，是「是否承认裸名引用」。② 的实现必须**展开到同裸名的精确键**；只剔除「裸名本身被引用」会少算一截，属错误实现。
> ④ 与 ①②③ 的差异源于工具内部回退逻辑，**不是算错**。

对外引用无入边数字时，必须带上口径编号或全名。

### 2.7 分母链

```
total_nodes    = len(edges.keys())
with_file_map  = 有 file_map（full_id 优先，回退裸名）
instrumentable = 有 file_map 且非汇编（同名同文件去重）
real_denom     = instrumentable − macro − unused − ffprobe
touched        = D 层 trace 触达（限定在 instrumentable 内）
nt             = real_denom − touched          ← 集合差
target_set     = nt − SIMD
```

**触达率**（不称“覆盖率”，理由见 §11）**两个口径，都要标**：

| 口径 | 公式 |
|:--|:--|
| 唯一对外口径 | `touched / instrumentable` |
| 收紧口径 | `touched / real_denom` |

**字段覆盖与同义名**：`data/denominator.json` 的 `values` 有 16 个字段，`definitions` 只给其中 12 个写了定义；缺的 5 个按下表补（与报告 §6.2.2 同源）。另有两组同义名：`values.with_inbound_all` = `definitions.with_inbound`；`values.total_nodes` = `definitions.total_nodes_graph`。数值只在 `data/denominator.json`，本表不重复。

| 字段 | 定义 |
|:--|:--|
| `macro` | 宏名被误识别为函数的节点（剔除项）|
| `unused` | 未启用的代码路径（剔除项）|
| `ffprobe` | 仅 ffprobe 侧使用、不在本图库口径（剔除项）|
| `real_denom` | `instrumentable − macro − unused − ffprobe` |
| `touched` | D 层 trace 在 `instrumentable` 内的触达函数数 |

### 2.8 分母的隐性口径（复算对不上时看这里）

`instrumentable` 不是「有 file_map 的节点数减去汇编节点数」这种朴素减法，它含**同名同文件去重**，朴素算法会多出几百个。

`nt` 是**集合差，不是数值差**：
```
nt = |real_denom − touched|      ← 正确
nt = |real_denom| − |touched|    ← 错误
```
两者差的那一小撮，来自「触达集里有落在 `instrumentable` 之外的元素」——它们是宏产物，属设计内。

### 2.9 自环四分类（判据须语言感知）

| 类 | 判定 |
|:--|:--|
| **真递归** | 函数体内存在独立的自调用语句 |
| 结构性不可解 | 只有取地址 / 赋给字段，无自调用 |
| 可过滤 | 文件内该符号的调用形态出现 0 次 |
| 无法定位 | 裸名节点，无源文件路径 |

判据必须按语言分派，否则会误杀汇编自环：

- `.s` / `.asm` → 跳转指令形态（`b` / `bl` / `bne` / `beq` / `b.<cond>` / `jmp` / `call` / `j*` 后跟标签）
- `.c` / `.h` → `sym(` 且排除「定义行 / 取地址 `&sym` / 赋值 `= sym` / 字段赋值 `.field = sym`」

> **可失败负例**：汇编文件里的一个递归标签（`bne <self>`），必须落「真递归」，不得落「可过滤」。只用 C 形态判据会把它判错。

### 2.10 缺陷定义标准

见 §3。

### 2.11 严格自环的物理边界

插桩机制只能看到「**函数入口地址 + 调用点地址**」，**看不到调用指令本身**，因此无法区分「真递归」与「经函数指针间接调用」。

要区分必须做**指令级反汇编**（逐条解析调用点），成本数小时 + 大内存，收益极小 → 不修。这就是为什么自环存在「结构性不可解」这一类，且它**不算缺陷**。

### 2.12 互证率 `matched_rate`

> **口径名**：`matched_rate`（互证率）。引用时须带此名，禁裸写「互证率 X%」。

定义：运行时边集合 `R` 中，有多少条能在静态侧找到同一条边（identity 粒度）。

```
S = 静态族边：sources 含 static 或 static-reg， 且不含 asm
R = 运行时边：sources 含 runtime
matched_rate = |R ∩ S| / |R|        identity 粒度 = key 的 name@file
```

**本节刻意不给数值表**（遵守本文开头纪律）。三件事只在一处：

| 什么 | 唯一位置 |
|:--|:--|
| 期望值 / 容差常量 | `scripts/verify_matched_rate.py` 的 `EXP` |
| 复算命令 | `python scripts/verify_matched_rate.py <graph>` |
| 报告里的叙述与表格 | `report/ACD-ffmpeg-报告-v4.0.md` §5.1 |

结构上恒成立的两条闭合（不依赖具体值，改图也成立）：

```
|R| = |R ∩ S| + |仅运行时|
|S| = |R ∩ S| + |仅静态|
```

**坐标纪律**：

- 不是 precision / recall —— 只说明「静态也认为有这条边」，不说明「这条边一定对」。
- 不与触达率、锚定率相除或比较（不同轴，数值相近纯属巧合）。
- 「仅静态」**不等于静态错误**：含「注册未调用」+「测试未覆盖」两类，未逐条定性。

> **负例（必须可失败）**：join 降级为裸名粒度必须得到不同的率。若两种粒度给出同一个数，说明 identity 粒度没生效，判据失效。

## 3 什么算缺陷

只有满足以下任一条件才算缺陷：

| # | 条件 |
|:--:|:--|
| 1 | **影响调用链正确性**：边指向错误、上下游关系错 |
| 2 | **导致消费方误判**：如按精确键匹配失败、把兜底语义当错值 |

以下**都不算缺陷**（设计正确行为 / 机制上限）：

| 项 | 为什么不修 |
|:--|:--|
| 外部符号无 file_map（`abort` / `usleep` / `__builtin_clz` / Win32 / COM）| 无源码，本就无法登记 |
| 同名不同文件不猜 | 不猜是对的，猜了会错连 |
| `file_map[裸名]` 单值 | 兜底语义，非「你要的那个副本」（见 §10.2）|
| 裸名节点不写 caller/callee_id | 设计如此 |
| `callee_id` 为空 | 裸名 + 外部符号，两种来源都是设计 |
| 真递归自环 | 运行时层记录正确 |
| 触达率未达 100% | 运行时层的机制上限（只能跑测试采边）|
| 注册表边的被调用方是「表名→成员」字符串 | 结构上无法给函数节点加入边 |
| 汇编层触达率低 | 真实态（绝大多数汇编符号是真叶子函数）|
| 某个叶子函数入边为 0 | 归因正确，源码调用点未解析成该形态 |

> **违反此标准去报「缺陷」= 制造无效返工。** 本仓宁可公开边界，也不把边界包装成待办。

## 4 `gap_class` 六分类

图上每个节点带一个 `gap_class`。它**不是缺陷标记**，是「这个节点为什么没有入边」的归因标签。

| `gap_class` | 定义 |
|:--|:--|
| `HAS_INBOUND` | 有入边（静态 / 运行时 / 汇编 / 注册表任一）|
| `DEAD_SUSPECT` | 无入边 + 有 file_map + 非汇编/SIMD + **DSP 命名特征**（`*_c` / `*_<数字>` / `avg_*` / `put_*` / `pred*` / `dc_*` / `add_*` / `sub_*` / `mul_*` / `ssd_*` / `sad_*`）|
| `UNKNOWN_DYNAMIC` | 无入边 + 有 file_map + 非汇编/SIMD + 非 DSP 命名 + **在可插桩集内**（函数指针表成员候选）|
| `UNCOVERED` | 无入边 + 有 file_map + 非汇编/SIMD + 非 DSP + 不在可插桩集（无法解释）|
| `UNKNOWN_ASM` | 无入边 + 汇编路径（`.asm` / `.S`）或裸名命中汇编符号表 |
| `NO_FILE_MAP` | 无入边 + file_map 查不到（full_id 与裸名回退均 miss）|

**为什么是六类而不是五类**：`UNCOVERED` 在四类互斥穷尽的构造下天然为 0（有 file_map 而无入边的节点，要么落 `UNKNOWN_DYNAMIC`，要么落 `DEAD_SUSPECT`）。查看器的图例因此只显示 5 种颜色。**这不是少了一类，是那一类当前为空。**

**文件归属口径**：`gap_class` 判「节点归属哪个文件」用 `full_id 优先、回退裸名`，**不用精确键查**。因为 `file_map` 并不覆盖所有消歧键（有数千节点精确键无条目、裸名有），若用精确键查会与分母口径分叉。

**三级闭合（每层都能失败）**
1. 全图层：无入边五类之和 = 总节点 − `HAS_INBOUND`
2. 目标集层：`nt − SIMD − with_inbound_in_nt = no_inbound_non_simd` —— 这是分母工具的内部推导式，**不是从 `gap_class` 数出来的**
3. 有入边层：`HAS_INBOUND = 总节点 − 无入边五类之和`

> 第 2 层若改成「从 `gap_class` 直接数」，会与分母值差几十条。根因是两套 SIMD 判定不同源（一边用自算的 SIMD 集合，一边用汇编符号表交集），**两者都正确，不可互否**。

当前图（`b357bf8e`）的分布可在查看器图例中直接读；机器可读值为 [`data/denominator.json`](../data/denominator.json) 同批产物。

## 5 已知边界（8 条，不修）

| # | 边界 | 为什么不修 |
|:--:|:--|:--|
| 1 | 严格自环（数量随图变化）| 绝大多数是真递归，运行时层记录正确；少数需指令级反汇编，成本远超收益 |
| 2 | 裸名被调用方无 file_map | 外部符号（`abort` / `usleep` / `__builtin_clz` / Win32 / COM），无源码 |
| 3 | 裸名被调用方多文件 | 同名不同文件，不猜是对的 |
| 4 | 裸名节点无 caller_id | 设计：裸名节点不写 ID |
| 5 | 触达率未达 100% | 运行时层机制上限（只能跑测试采边）|
| 6 | 注册表边形态（被调用方是「表名→成员」）| 结构上无法给函数节点加入边 |
| 7 | 汇编层触达率 x86 偏低 | 真实态：绝大多数汇编符号是真叶子函数，不存在调用者 |
| 8 | 个别叶子函数入边为 0 | file_map 归属正确；源码调用点未解析成该形态 |

> 边界性质不随图变；每条的具体数量随图变化，故本表**不列数值**——要数值请查 `denominator.json` 或现场复算。

## 6 注册表层（C 层）为什么冻结

注册表层（函数指针表反推）实测收益极低：**可补 36 点**，占**注册表候选 11,216** 的 **0.32%**，占**全图 114,175 条边**的 **0.031%**；而全量重建需 90–100 分钟，且会改变图 md5、触发整条口径链重绑。

**冻结裁定附带一个可失败判据**：将来若有人要重启这一层，必须先证明「可补点 ÷ 注册表候选 > 1%」；当前 **36 / 11,216 = 0.32%**，不达标，不批。

> 三个分母别混：**36 / 11,216 = 0.32%**（可补点占注册表候选，冻结判据用这个）、**36 / 114,175 = 0.031%**（占全图边）、**5 / 14,668 = 0.03%**（C 层历史收盘率：申报 14,668 点、收盘 5 点）。另有 **92 / 2,727 = 3.37%**（全部候选缺口占成员函数指针调用点，含误报与平台特定代码，不是"可补面"）与 **36 / 2,727 = 1.32%**（可补点占同分母），见报告 §6。

> 这条判据的存在，比冻结结论本身更重要——它把「不做」变成了可被推翻的断言，而不是一句态度。
>
> 另有一条防误判记录：曾有人用**旧一轮产物**的候选数（305）当现值（实测 11,216），据此得出「收益可观」。**引用该层数字前必须现场重算，禁从历史产物反推。**

## 8 两个图锚为什么并存（以及 stale 规则）

| 锚 | 时间 | 说明 |
|:--|:--|:--|
| `d690c09e…` | 2026-11-11 | 报告体写作时依据的建图产物 |
| `b357bf8e…` | 2026-11-14 | 同一次建图的文件被重写，字节 +279 B，md5 变化 |

那 279 字节只涉及**跨语言边的元数据字段**，节点数、边数、目标集**逐项一致**，16 项自洽判据在新图上 16/16 通过。

```
图 md5 ≠ 本文锚  →  一切派生数字 stale  →  禁引用，须重算
```

核对顺序永远是：**先比 md5，再看数字。** 数字对不上而 md5 相同 → 是复算方法问题；md5 不同 → 数字全部失效，不要解释。

## 9 防误判记录（已真实发生过）

这些坑都踩过一次并被拦下，写出来是因为它们比成绩更能说明这套口径的边界在哪：

| 误判 | 真相 |
|:--|:--|
| 拿汇编符号表条目数（7,420）当「图内汇编节点数」| 图内汇编节点是**键名以 `.asm`/`.S` 结尾的节点**，两者口径不同，差数千 |
| 用「全量一致率」判 `callee_id` 不合格 | 空值是设计；只能用**非空一致率** |
| 报「`file_map[裸名]` 单值导致数千节点错位」| 裸名条目是**兜底语义**，不是「你要的那个副本」；消歧走 family index |
| 从 `gap_class` 数出目标集无入边数，去否定分母工具值 | 两套 SIMD 判定不同源，差几十条，**两者都正确** |
| 拿旧一轮产物当现值 | 每层候选数随图变化，必须现场重算 |

## 10 消费者须知

### 10.1 一律 `json.load`，禁止字节 diff
图文件序列化格式随版本变过：某代曾压成紧凑格式（约 60 MB），当前为缩进可读格式（约 106 MB）。**字节 diff 会把「格式变化」误判成「内容全变」**。正确做法是解析后比结构（节点集 / `calls` 键集 / 顶层字段）。

### 10.2 三种「查定义文件」的语义

| 你要什么 | 查什么 |
|:--|:--|
| 某个**特定副本**的定义文件 | `file_map[精确键]` |
| 该符号**是否存在** / 任一合法定义 | `file_map[裸名]`（兜底语义）|
| **消歧到正确副本** | family index（按调用方文件匹配），不要自己拿裸名猜 |

### 10.3 `callee_id` 为空是正常态
空值只有两个来源：裸名被调用方（不写 ID）、外部符号（无节点可指）。判「边是否指对」只看**非空部分**。

## 11 措辞纪律

对外表述上，以下说法一律不许出现：

| 禁止 | 只能说 |
|:--|:--|
| 「覆盖率 X%」（会与 gcov 的行/分支覆盖混淆）| 「函数**触达率** X%（`touched / instrumentable`）」 |
| 「触达率 100%」 | 「已触达 X%，未触达节点逐类归因见 `gap_class`」 |
| 「支持 C」 | 「在 FFmpeg 9.1-dev / MinGW-w64 / x86_64 上完成实证」 |
| 「调用图已完整」 | 「X% 覆盖 + 未覆盖部分五类归因」 |
| 「死代码」 | 「`DEAD_SUSPECT`（疑似，未证实）」 |
| 「解析全对」 | 「N 项自洽判据全通过，隐含边界见 §5」 |
| 「已修复所有问题」 | 「已知边界 8 条仍在，理由见 §5」 |

## 12 自己复算

```bash
# 16 项自洽判据（当前图期望 16/16 PASS）
python scripts/verify_graph.py acd_graph.json

# 把触达率分母从头算一遍（默认只算不写，加 --write 才落盘）
python scripts/denominator_recompute.py \
  --graph acd_graph.json --build-root <构建目录> \
  --asm <asm_capstone_map.json> --touched <edges_fate_*.json> \
  --compare data/denominator.json

# 重新导出查看器视角
python scripts/export_views.py --graph acd_graph.json
```

分母复算会用到本仓 `data/denominator_excluded_lists.json` 的三份剔除名单（macro / unused / ffprobe）——没有它们，分母只能信、不能算。

数值请始终对照 `data/denominator.json`，不要对照本文档——本文档刻意不含数值表。
