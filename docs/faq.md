# FAQ · 七个最常问

> **English → [faq.en.md](faq.en.md)**

## 1. 能不能把我的仓库也建一张图？

**本仓不含构建引擎**：只交数据、方法、判据与口径。两条路径：

- **等引擎侧工具链**：另行发布；本仓不预告时间。
- **自建**：按 [`reproduce.md`](reproduce.md) 复刻 A（宏展开）/ B（静态）/ D（运行时）/ asm + static-reg 四路，再按 [`caliber.md`](caliber.md) 的合流口径合并。

手上真有百万行级、还在持续更新的 C/C++ 工程（含汇编更好），走 [建图可行性模板](../.github/ISSUE_TEMPLATE/feasibility-request.md)，留 repo 地址与规模（行数 / 语言构成 / 是否含汇编 / 更新频率）。我们回**一次**可行性判断：能不能按同一口径出图、粗估工期、哪部分预计拿不到。**判断不出来也会直说；不承诺排期。**

## 2. 我下载的图和报告里的 md5 不一样？

两个锚点：报告体依据 `d690c09e`（**不随仓、不随包分发**，不对读者开放），发布包实物 `b357bf8e`。两者字节差 279 B（仅跨语言元数据），聚合数字逐项一致，且 16 项判据在新图 16/16 PASS。**核对请以你下载文件的实际 md5 为准**，细节见 [`anchors.md`](anchors.md)。

## 3. 49.74% 是覆盖率吗？

不是。本仓只用「函数**触达率**」（`touched / instrumentable`）——既不是行覆盖，也不是分支覆盖；叫覆盖率会与 gcov 口径混淆。定义见 [`caliber.md`](caliber.md)。

## 4. 26.50% 的交叉确认率是不是太低？

剩下 **73.50%** 是单源独有边——按定义就不可能被两路同时看到。「26.50% 交叉」与「73.50% 独有」是同一件事的两面，不是"质量只有 26%"。

## 5. `static-reg` 那 8,571 条能当实际调用用吗？

不能。语义是"**可能**被调用"（函数指针表里挂了这个函数），全部 low 置信。引用时必须写明"可能性，非实际发生"。

## 6. 引用 / 转载怎么引？

用 [`CITATION.cff`](../CITATION.cff)，并且**任何数字都要带图 md5 + FFmpeg commit**。哪些能引、哪些必须带限定、哪些禁止引，见报告 §10。

## 7. 查看器里怎么只有几百个节点？

因为**它不是全图**。`viewer/acd-viewer.html` 内嵌的是 **3 个手挑切片**（按 focus + depth 2/2/3 取的邻域，分别对应解码主路径、汇编交叉点、未触达盲区），合计 **414 节点 / 1,147 边**，只占全图 38,697 节点 / 114,175 边的 **1.07% / 1.00%**。查看器里四处都标了这个占比：顶栏徽标、画布下提示、右栏账目、页脚右下。

想看全量请用 `scripts/query.py`（纯标准库，直读 zip，不用解压那 106 MB），或按 [`reproduce.md`](reproduce.md) 自建查看器。为什么不内嵌全图：114,175 条边塞进单文件 HTML 会大到几十 MB，浏览器也画不动。

## 附：体积到底多大？
